# 机器人部署与运维手册

面向"把系统装到教室里那台机器人/平板上，每天开机就能用"的场景。
接口与链路细节见 [README](../README.md)，接模型见 [LOCAL_MODELS.md](LOCAL_MODELS.md)。

---

## 1. 部署前检查

| 项 | 要求 | 怎么确认 |
| --- | --- | --- |
| Python | 3.10+ | `python -V` |
| 依赖 | `pip install -r requirements.txt` 无报错 | 装完跑 `python _tools\check_imports.py` |
| 数据目录 | `data/` 可写，磁盘留 1GB 以上 | 首次启动会自动建库与目录 |
| 端口 | 默认 8000，未被占用 | `netstat -ano \| findstr :8000` |
| `.env` | **必须设 `SECRET_KEY`** | 不设则每次重启随机生成，老师要被踢下线重登 |
| 口令 | 用 `scripts\install.ps1` 生成随机口令，或手动改 `.env` 的 `TEACHER_PIN` / `ADMIN_PIN` | 改完重启生效 |

`SECRET_KEY` 生成一条：`python -c "import secrets;print(secrets.token_hex(32))"`，粘进 `.env`。

## 2. 启动与开机自启

### 2.1 手动启动

```bash
scripts\run_server.bat
```

控制台会打印监听地址、数据目录、五个引擎模式、是否演示模式、教师口令——这几行就是现场排障的第一手信息。

### 2.2 Windows 开机自启

`scripts\install.ps1` 会把 `scripts\run_server.bat` 的快捷方式放进当前用户的「启动」目录，登录即自动跑。
手动改的话：「任务计划程序」→ 创建任务：
- 触发器：**登录时**（或开机时）
- 操作：启动 `scripts\run_server.bat`
- 勾选「不管用户是否登录都运行」时注意：`getUserMedia` 需要有人在前台登录的桌面会话，机器人必须保持登录状态

重启机器验证一次：`curl http://127.0.0.1:8000/healthz` 应返回 `"ok": true`。

### 2.3 Linux 开机自启（systemd）

```ini
# /etc/systemd/system/reading-ai.service
[Unit]
Description=Reading AI Companion
After=network.target

[Service]
WorkingDirectory=/opt/reading-ai
Environment=HOST=0.0.0.0
Environment=SECRET_KEY=换成你自己的
ExecStart=/usr/bin/python3 run.py
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

`systemctl enable --now reading-ai`，日志用 `journalctl -u reading-ai -f`。

## 3. 网络、https 与摄像头

| 访问方式 | 摄像头 | 屏幕共享 | 文件/粘贴 |
| --- | --- | --- | --- |
| `http://127.0.0.1:8000`（设备本机） | 可用 | 可用 | 可用 |
| `http://192.168.x.x:8000`（局域网 IP） | **自动降级为「系统相机」**（手机/平板仍能调起相机） | 置灰并说明原因 | 可用 |
| `https://…`（配了证书） | 可用 | 可用 | 可用 |

这是浏览器安全上下文的硬限制，不是代码问题。要在机器人上用网页内摄像头，从下面选一个：

1. **设备本机访问**：机器人上装一个浏览器，指向 `http://127.0.0.1:8000`。
2. **反代加 https**：Caddy 最省事，`caddy reverse-proxy --from reading.local --to 127.0.0.1:8000`。
3. **接受降级**：局域网 http 下用「系统相机」拍照，流程完全一样，只是多一次系统相机界面。

局域网访问需要 `.env` 里 `HOST=0.0.0.0`（默认只监听本机）。

### 3.1 不同机器人、屏幕与输入方式

不需要“适配型号”，前端只问能力。`device.js` 启动时探测屏幕/内存/浏览器能力，写到
`<html data-screen>`，CSS 据此分三档：

| 设备类型 | 典型屏幕 | 布局行为 |
| --- | --- | --- |
| 小屏陪伴机器人 | 7 寸，480×800 级 | `compact`：字号缩小、主按钮撑满宽度、画面高度压到 30vh |
| 平板 | 10 寸，1200×1920 级 | `regular`：常规布局，触控目标 ≥ 48px |
| 一体机 / 横屏 | ≥ 1280 宽 | `wide`：问题字号用 `clamp()` 自适应，横屏时压缩垂直留白 |

另外两项与屏幕无关的适配：

- **输入方式**：机器人上通常没有键盘，提问后直接「按住说话」录音回答；录音在本地转成
  16k 单声道 WAV（最长 10 秒）再上传，和打字回答走同一条链路。不支持录音的设备会自动
  收起语音按钮，保留文字与图标选项。接键盘的机器人可以空格键按住说话。
- **摄像头**：面板会列出设备上的所有摄像头（平板前后置、外接 USB），选过一次就记住；
  外接摄像头拔掉后再拍，会自动回退到默认后置，不会卡在“打不开”。
- **翻页自动拍**：对着绘本进摄像头/屏幕预览，翻页后自动拍下并自动提交，孩子不用每页按按钮；
  面板里有开关（默认开），自动拍后有 1.5 秒反悔窗口。画面没动、手挡住、还没对焦时不会误拍，
  拍糊了仍然会被质量闸门拦下并提示重拍。
- **网络摄像头**：机器人/平板自己没有可用摄像头（或视角不对），就接 ESP32-CAM / 手机 / 电脑；
  取图面板选「网络摄像头」填一次地址就记住，预览、抓帧、翻页自动拍都能用。详见下节。

浏览器最低要求：Chrome / Edge 80+、Safari 14+、Android WebView 80+。
旧浏览器会在机器人页顶部显示升级提示，不会静默地“按钮没反应”。

### 3.2 网络摄像头：ESP32-CAM / 手机 / 电脑 USB / RTSP

取图面板里的「网络摄像头」只要一个地址：**能返回一张 JPEG 的 http 地址**。
按设备抄下面的填法（整条链路都在局域网内，不访问外网）：

| 设备 | 填什么 | 备注 |
| --- | --- | --- |
| ESP32-CAM | `http://<esp32-ip>/capture` | CameraWebServer 示例自带；把绘本卡在支架上、分辨率设 640×480 或 800×600 就够 |
| 手机（IP Webcam / DroidCam 等） | `http://<手机-ip>:8080/shot.jpg` | 以 App 启动页显示的「抓帧地址」为准；手机与机器人要连同一个 WiFi |
| 电脑 USB / 内置摄像头 | 面板里填 `camera:0`（第二个写 `camera:1`） | 服务端直接拍帧，不用另开桥接 |
| 只能用 http 地址的旧机器人 | 先跑 `python _tools\camera_bridge.py`，再填它打印的 `http://<电脑-ip>:8081/capture` | 外接 USB 常是 `--index 1`；`--size 1280x720` 可调 |
| 只给 RTSP 的老机器人/网络摄像头 | `python _tools\camera_bridge.py --url rtsp://<摄像头-ip>:554/...` 然后用桥接的 http 地址 | 浏览器不能直放 RTSP，必须转一道；面板里直接填 `rtsp://` 会当场提示 |
| 要网页登录的摄像头（海康/大华等） | `http://<账号>:<密码>@<摄像头-ip>/<抓帧路径>` | Basic / Digest 都支持；密码里有 `@`、`:` 时先在摄像头后台换一个简单密码 |

工作方式：

- **预览**：`<img>` 直连摄像头地址（不读像素，不受跨域限制）；MJPEG 流（地址带 `stream/mjpeg`）
  设一次 `src` 就一直播。浏览器所在网段连不到摄像头时，自动改由服务端转发预览。
- **抓帧**：浏览器读不到跨域像素（canvas 会被污染），所以抓帧走
  `/api/camera/snapshot?session_id&token&url`，由服务端代抓。服务端只允许 **http + 解析后全部是
  局域网/环回 IP** 的地址，不跟随重定向、只收图片、单帧 ≤ 8MB，校验过的 IP 直接钉进请求
  （Host 头保留原名），防 DNS 重绑定——不会变成访问外网的跳板。
  单帧地址（`/capture`、`/shot.jpg`）直接取；只给 MJPEG 流的摄像头会从流里抠出第一张完整的 JPEG 就断开，
  不让服务端一直挂着。
- **自动翻页**：网络上按 1.5 秒一帧的节奏采样（ESP32 扛不住高频），翻页后自动拍、1.5 秒后自动提交。
  MJPEG 流也能抓帧，但优先填 `/capture` 这类抓帧地址，省摄像头资源。
- **登录**：摄像头网页要账号密码时写进地址即可：服务端先试 Basic，收到 Digest 挑战会自动重算
  （海康/大华常见），不用装额外工具；带凭证的地址浏览器不许 `<img>` 直连，预览自动走服务端转发。
- **隐私**：不保存任何帧，只记住地址（浏览器 localStorage，最多 8 个，可删）。

排错顺序：先在 `/device-check` 的「网络摄像头」块试连（直连能不能看到画面）→
再在取图面板里连接（这一步验证服务端代抓）→ 最后拍照看质量闸门是否放行。

### 3.3 换设备先跑自检页

浏览器打开 `/device-check`（不需要登录，不读孩子数据）：

| 检查项 | 合格的标志 |
| --- | --- |
| 能力清单 | 安全上下文/摄像头/麦克风/录音/WebSocket/ES2020 六项全 ✅ |
| 摄像头 | 点开后能看到实时画面，提示里带「有画面」；多摄像头可切换 |
| 网络摄像头 | 填地址点「试一下」后有画面（分辨率、耗时）；试通过的地址会记进取图面板 |
| 麦克风 | 说话时绿色条跟着动 |
| 喇叭 | 点「播一声」听到叮 |
| 网络 | 往返平均 < 200ms（< 50ms 很好） |

页面底部「复制设备信息」会把设备 ID、屏幕、UA、能力清单打包成文本，出问题时直接粘给技术老师。

## 4. 会话生命周期

1. 老师在教师端点「开始共读」，选孩子和绘本 → 生成一次性链接 `/robot?session=…&token=…`。
2. 机器人在这个链接上打开：先收到 `snapshot`（当前状态、上一页问题、孩子姓名），断线重连也靠它复原。
3. 一次会话默认最多 60 页（`PAGE_LIMIT_PER_SESSION`）。
4. 老师点「结束共读」后：
   - 机器人与 `4401`/`4404` 关闭，停在"这次共读已经结束了"，不再重连；
   - 本场 TTS 播放缓存被删除，工作内存清空。
5. **服务重启不会杀死进行中的会话**：会话状态在 SQLite 里，设备重连时 `SessionRuntime.load()`
   从库里重建（孩子、绘本、最近 3 轮问答），可以由机器人继续往下读。
   正在进行的"识别中"任务会丢，重新拍这一页即可。

一次会话 = 一台设备。两个设备用同一个链接会互相抢，老师给每台机器人各自开一次会话。

## 5. 运行时状态怎么看

| 想看什么 | 在哪看 |
| --- | --- |
| 服务活着吗 | `GET /healthz`：版本、`demo_mode`、各模型模式 |
| 机器人连接状态 | 机器人页顶部状态条：`实时` / `重连中` / `兼容模式` / `已结束` |
| 每步识别与自检 | 教师端会话页实时事件流（识别结果、摘要、问题、检查项） |
| 各阶段耗时、最慢页面 | 教师端「运维」面板，读 `metrics` 表 |
| 谁做了什么敏感操作 | `audit_log` 表（老师登录、建会话、结束会话、改题库、清数据） |
| 启动与异常 | `data/server.log`（控制台也同步打印），搜索 `Traceback` |

状态条含义：

- **实时**：WebSocket 正常，心跳每 15s 一次。
- **重连中**：连接断了，正在退避重连（最多 3 次）。
- **兼容模式**：连续 3 次连不上，已切 HTTP 轮询（2s 一次）+ 表单上传，功能不变、只是多几十毫秒延迟。
- **已结束**：会话被结束或链接无效，不再重连。

## 6. 常见故障处理

| 现象 | 先查什么 | 处理 |
| --- | --- | --- |
| 机器人空白/打不开 | `curl http://<ip>:8000/healthz` | 服务没起：看 `data/server.log`；起了：查防火墙、`HOST` 是否 `0.0.0.0` |
| 一直「重连中」后转「兼容模式」 | 教师端还开着吗、网线/WiFi | 兼容模式本身可用；恢复网络后刷新页面即回「实时」 |
| 提示「这次共读已经结束了」 | 老师是否点了结束、服务是否重启过 | 重新开一次会话，发新链接 |
| 拍照按钮没反应 | 是不是局域网 http | 见 §3：改本机访问 / https / 用系统相机 |
| 屏幕共享按钮是灰的 | 同上，非安全上下文 | 用文件或粘贴 |
| 一直「正在看这张图」后提示重拍 | `metrics` 里该页 `page_total` 是否异常、模型服务是否在 | 模型挂了会自动降级到规则版并在界面标演示模式；网络断了看下一条 |
| 识别成功但没声音 | 设备音量与浏览器自动播放策略 | 机器人上首次交互（按按钮）后才允许播放；确认 TTS 模式不是 stub |
| 质量检测总说"太糊" | 环境光、距离、屏幕摩尔纹 | 拍的时候让页面占画面 2/3；电子绘本建议直接截图而不是拍屏幕 |
| 老师被反复踢下线 | `.env` 是否缺 `SECRET_KEY` | 补上并重启 |
| 磁盘越来越大 | `data/tts/` 残留 | 启动时自动清理 7 天前的；异常关机残留可手动清空该目录 |
| 麦克风按钮不见了 | `/device-check` 里「麦克风/录音」是否为 ❌ | 设备不支持录音时按钮会自动收起；可接 USB 麦克风或用文字/图标回答 |
| 接的 USB 摄像头没画面 | `/device-check` 里能否切换摄像头 | 在自检页选中外接摄像头；机器人页会记住这个选择；拔掉后自动回退 |
| 网络摄像头连不上 | 自检页「网络摄像头」块能否看到画面；提示里的原因 | 核对 IP/端口、摄像头是否通电、是否同一 WiFi；ESP32 用 `/capture`、手机用 `/shot.jpg`；只给 RTSP 的要先跑 `camera_bridge.py --url` |
| 网络摄像头预览是黑的、抓帧却能用 | 面板提示是否写着“已改由服务端转发预览” | 正常：浏览器与摄像头不在一个网段，预览由服务端代转，抓帧不受影响 |
| 填了网页地址报“返回的不是图片” | 地址是否指到了摄像头首页 | 换成抓帧地址：ESP32 `/capture`、手机 `/shot.jpg`；桥接脚本用 `/capture` |
| 报“这台摄像头要登录” | 地址里是否带账号密码 | 写成 `http://账号:密码@摄像头IP/路径`；账号密码错也会报 401，去摄像头后台核对 |
| 小屏上按钮被遮住 | 是否全屏、是否横屏 | 点右上角 ⛶ 全屏；小屏布局会自动把主按钮撑满宽度 |

## 7. 验收清单（每次上架/换机跑一遍）

```bash
python -m pytest tests -q            # 应为 100 passed
python _tools\check_imports.py       # 无报错
python run.py                        # 另开一个终端
python _tools\live_smoke.py          # 全程断言通过，证据落 _tools\shots\live_smoke.json
```

- [ ] `/healthz` 返回 `ok: true`，`demo_mode` 符合预期（没接模型就该是 true）
- [ ] `/device-check`：六项关键能力全 ✅，摄像头画面、麦克风电平、喇叭、网络往返都正常
- [ ] 教师端能登录，能开一次会话并拿到机器人链接
- [ ] 机器人端：拍照 → 出摘要与问题 → 答题 → 有语音
- [ ] 拔掉网线 10 秒再插回：状态条从「重连中」回到「实时」，页面可继续拍
- [ ] 老师点「结束共读」：机器人显示"已经结束了"，不再重连
- [ ] 重启服务后，未结束的会话链接重开仍能继续（snapshot 复原）
- [ ] 家长链接只读、能撤回授权
- [ ] `data/tts/` 在结束会话后没有新增残留

## 8. 已知限制

- **单进程内存态**：事件总线与会话运行时在进程内，只能单实例部署；要横向扩，需要换 Redis 共享层。
- 一台设备对应一次会话，不要多个设备共用一个链接。
- 拍照质量阈值按 720p 教室实拍标定，换广角/微距摄像头需重新标定（`app/services/vision.py` 顶部）。
- 服务重启会丢失"正在识别"的那一页（重新拍即可），不丢已完成页与问答记录。
