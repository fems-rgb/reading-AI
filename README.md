# 绘本阅读陪伴 AI 智能体

给 3-6 岁孩子共读绘本时用的"看一眼、问一句、听一句"的陪伴系统：
机器人/平板拍下绘本页面 → 本地模型生成三层摘要与一个问题 → 孩子口头回答 → 系统回应并把
这次共读整理成教师教学建议与家长周报。

全部推理在园内完成（RapidOCR + Qwen2.5-VL + Qwen2.5 + faster-whisper + Windows 系统语音），
**默认不访问任何外网**，代码里有硬约束而不是口头承诺。

---

## 1. 装好就能用（Windows 一台电脑跑全链路）

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install.ps1   # 装环境 + 下模型 + 生成 .env + 开机自启
scripts\run_server.bat                                        # 启动
```

前置：Python 3.10+、[Ollama](https://ollama.com/download)、ffmpeg（`winget install Gyan.FFmpeg`）。
完整步骤与故障处理见 [docs/DEPLOY.md](docs/DEPLOY.md)。

打开：

| 入口 | 地址 | 谁能用 |
| --- | --- | --- |
| 首页 | http://127.0.0.1:8000/ | 任何人（只显示概况） |
| 教师端 | http://127.0.0.1:8000/teacher | 老师口令（`.env` 的 `TEACHER_PIN`） |
| 机器人端 | 教师端点「开始共读」后生成的链接 | 该次会话的设备 |
| 家长卡片 | 教师端「周报与授权」里的家长链接 | 家长（一次性随机 token） |
| 设备自检 | http://127.0.0.1:8000/device-check | 任何人（不读孩子数据） |

首次启动是**空库**：老师在教师端录入本班孩子与绘本页，或直接在机器人端点「拍第 1 页」随拍随读。
`SEED_DEMO=1` 才会铺一套示例孩子/绘本，只给开发与验收用。

自带的五个引擎默认全部真实：OCR（RapidOCR）、看图（qwen2.5vl:3b）、语言（qwen2.5:3b）、
童声识别（faster-whisper）、语音合成（系统中文女声）。只要有一个环节退回 `stub`，
首页与 `/healthz` 会明确标「演示模式」，不假装模型已经接好。

改用园内 GPU：见 [docs/LOCAL_MODELS.md](docs/LOCAL_MODELS.md)，只改 `.env`，不改代码。

## 2. 一次共读长什么样

1. 老师选"孩子 + 绘本"，点「开始共读」，把生成的链接在机器人/平板上打开。
2. 孩子翻到第 1 页，按【拍第 1 页】——可以现场拍照，也可以选电脑里的图片、截屏、粘贴。
3. 页面质量先过闸（糊了/太暗/反光/太远 → 直接说人话让孩子重拍，不进模型）。
4. A1 文字识别 ‖ A2 画面理解并行 → A3 生成三层摘要 → A11 内容自检 → A4 提问 → A11 再检。
5. **先讲再问**：拍完先播放这一页的讲稿（同样过了闸门），讲稿有多长就等多久，
   再停 8 秒让孩子看画面，然后语音提问（答不出来先给图标二选一，再不行才请老师）。
6. 孩子说完 → A7 判断"听没听懂"（不打分、不贴标签）→ 回应 → 翻下一页；翻页会立刻
   取消上一页还在等待的提问与超时，不会串话。
7. 结束 → A10 生成 3-5 条**带依据**的教学建议 → 老师确认/修改/忽略 → 家长周报（老师发布后可见）。

教师端能实时看到每一步：识别结果、三层摘要、问题、每条自检结论与检查项。

### 图片来源：不止机器人摄像头

`app/web/static/capture.js` 提供统一的取图面板（`window.ImageSource.pick()`），两个入口
（机器人端主按钮 / 重拍、教师端「拍照 / 截图 / 粘贴」）都能用这五条通道：

| 通道 | 适合场景 | 实现 |
| --- | --- | --- |
| 摄像头 | 机器人/平板/笔记本自带或外接 USB 摄像头 | `getUserMedia`，优先后置摄像头，实时预览后点【拍下来】 |
| 网络摄像头 | ESP32-CAM、手机 IP Webcam、老机器人只给 RTSP/HTTP 的画面 | `<img>` 直接预览；抓帧由服务端代抓（同源代理，见下） |
| 本地图片 | 老师提前拍好、扫描件、绘本电子页 | `input[type=file]` |
| 屏幕截图 | 绘本在屏幕上（电子绘本、投影）、远程支援 | `getDisplayMedia` 选窗口/整屏 |
| 粘贴 | 截图后直接 Ctrl+V | document `paste` 事件取剪贴板图片 |

所有通道出来的图都会统一缩到**最长边 1600px、JPEG 0.85**再上传（低配设备自动降到 1280/1024），
避免平板原图把实时链路拖慢；原图不落盘（见 §6）。

**网络摄像头为什么不走浏览器抓帧**：摄像头固件不会发 CORS 头，`<img>` 能显示但 canvas 取不出像素，
https 页面还不能直连局域网 http。所以预览用 `<img>` 直连（失败时自动改由服务端转发），
抓帧走 `GET /api/camera/snapshot?session_id&token&url`：服务端校验设备凭证后只允许
**http + 解析结果全部落在局域网/环回**的地址，不跟随重定向、只认图片、单帧 ≤ 8MB，
校验通过的 IP 会直接钉进实际请求（Host 头保留原名，防 DNS 重绑定），
既不当 SSRF 跳板，也不把任何帧落盘。单帧地址（`/capture`、`/shot.jpg`）直接取；
只给 MJPEG 流的摄像头会从流里抠出第一张完整 JPEG 就断开，不让服务端一直挂着。
要网页登录的摄像头把账号密码写进地址（`http://账号:密码@<摄像头-ip>/...`）：Basic 直接带上，
海康/大华这类 Digest 会在 401 后自动重算，老师不用装额外工具。
取图面板里填一次地址就记住（`localStorage`），自动翻页在网络上按 1.5 秒一帧的节奏检测
（ESP32 扛不住高频请求）。

| 设备 | 填什么地址 |
| --- | --- |
| ESP32-CAM（CameraWebServer 示例） | `http://<esp32-ip>/capture` |
| 手机装 IP Webcam / DroidCam 等 | `http://<手机-ip>:8080/shot.jpg`（按 App 提示的抓帧地址） |
| 电脑摄像头（USB/内置） | `camera:0`（第 2 个摄像头写 `camera:1`），服务端直接拍帧，最稳 |
| 电脑摄像头但要 http 地址（旧机器人只认 http） | 先跑 `python _tools\camera_bridge.py`，再填它打印的 `http://<电脑-ip>:8081/capture` |
| 只给 RTSP 的机器人/网络摄像头 | 同一脚本 `--url rtsp://<摄像头-ip>:554/...`，把它转成 http（面板里直接填 `rtsp://` 会当场提示怎么转） |
| 只给 MJPEG 流的网络摄像头 | `http://<摄像头-ip>/stream`（预览直连，抓帧由服务端抠一帧） |
| 要网页登录的摄像头（海康/大华等） | `http://<账号>:<密码>@<摄像头-ip>/<抓帧路径>`（Basic / Digest 自动处理） |

⚠️ 浏览器规定：`getUserMedia` 与 `getDisplayMedia` 只在**安全上下文**（`https://` 或 `http://localhost`）
可用。用局域网 IP（如 `http://192.168.1.5:8000`）打开时，面板会把摄像头自动降级为「系统相机」
（`input capture=environment`，手机/平板仍能直接调起相机），屏幕共享按钮置灰并写明原因，
文件与粘贴始终可用。网络摄像头不受这条限制（图片由 `<img>` 或服务端取），
但 https 页面里浏览器不能直连局域网 http，会自动退回服务端转发预览。
两种不可用情况都是**明确提示**，不会静默失败。

## 4. AI 自检（规范里缺的那一环，已补上）

自检分三层，**裁判永远是确定性规则**，模型只负责"改一版"：

### 4.1 内容闸门（每条要念给孩子听的文本）

| 对象 | 检查项 | 不合格怎么办 |
| --- | --- | --- |
| 三层摘要 | 原文层必须等于 OCR（模型无权改写）、描述只含画面里看得见的实体、推测必须标注、每句 ≤15 字（英文 ≤12 词）、讲稿不得新增实体、不得推进剧情、语言与绘本一致 | 先让模型带着"不要提到 X"重写一次；仍不合格 → 降级为规则版安全摘要 |
| 提问 | 一次只问一个、长度适龄、不含抽象词、只问画面里的内容、不重复最近三题、封闭题每 3 题最多 1 道、语言一致、题型合法 | 同上；最后兜底 `safe_question()` 只用画面事实拼一个最短问题 |
| 教学建议 | 每条必须挂到具体问答 id、不排名不贴标签、≤60 字、3-5 条 | 丢弃无依据项，不生成"看起来很棒"的空话 |
| 家长周报 | 不排名、不含音视频、必须有监护授权 | 直接 422 拒绝生成 |

每次检查都写进 `selfchecks` 表，教师端每条问答下面都有徽章：
**自检通过 / 自检已修正 / 自检已拦截·降级**，点开能看到具体检查项、说明与处理方式。

### 4.2 运行自检（开场前）

数据库可写、磁盘空间、五个模型服务可达、无园外请求配置、绘本库是否有可用页、监护授权、
语音确认阈值。失败给人话提示 + 下一步，不把 `Connection refused` 甩给老师。
教师端顶部会在有问题时出现一条横幅。

**深度自检（真跑，不是看装没装）**：教师端 →「运维」→「深度自检」，或设备自检页的
「共读引擎」块。服务端现场生成一张带中文的测试卡片，真实调用 OCR 认字、VLM 描述画面、
LLM 回 JSON；再合成一句中文语音，把同一段音频喂回 ASR 与原文比对。五项都给出实测耗时
与识别结果，某项没过会直接给下一步（例如 `python scripts/fetch_models.py --only asr`）。

### 4.3 会话后自检

复盘记录是否完整、每条建议是否有依据、临时数据是否已释放（规范 §8 "无依据建议数 = 0"）。

### 4.4 怎么亲眼看到它拦

教师端 →「运维」→「内容闸门试跑」：用 6 个真实坏例子跑闸门
（画外实体"大象在哪里呀"、抽象词"心情"、超长句、重复上一题、一次问两件事、建议排名+无依据），
外加 1 个合格样例做对照。全部是纯规则，不调模型，随时可复现。

## 5. y.zip 遗留问题的处理

原型的可复用部分（"拍照 → 描述 → 提问 → 语音播报"链路、三个 WebSocket 消息类型）都保留了，
下面这些问题按规范 §1.3 逐条修掉：

| 原问题 | 现在的做法 |
| --- | --- |
| `.env.example` 里写着真实的百炼 API Key | 只留占位符；所有出站经 `guard.py` 校验，公网地址在发请求前就被拦。<br>**⚠️ 那个 Key 已经泄露过，请立刻到阿里云百炼控制台吊销并轮换** |
| `/analyze-page` 是同步 `def`，在事件循环里 `run_coroutine_threadsafe` 推事件 | 全链路 `async`；模型调用用 `asyncio.to_thread` 包，避免阻塞事件循环 |
| 全局 `_voice_session` 单实例，两个班同时用就串话 | `session_id → SessionRuntime` 字典 + 每会话 `asyncio.Lock`，翻页打断只取消本会话任务 |
| 提问交给语音模型"临场发挥"，可能问到画面里没有的东西 | OCR 与 VLM 分工，A3 只重组事实，A4 单独提问，A11 用词表校验接地 |
| 没有独立 OCR，全靠多模态模型猜字 | A1 用 PaddleOCR；库内页面直接命中预识别缓存 |
| 没有数据库，重启丢记录 | SQLite（WAL）+ 短连接，记录进 `sessions/turns/advice/weekly_reports/selfchecks/metrics/audit_log` |
| 没有测试、没有日志埋点、没有降级 | `tests/` 63 条用例；`metrics` 表记录每阶段耗时与 token；任一模型不可用自动降级为规则版，界面标「演示模式」 |
| 没有题库、没有绘本库 | 教师端可建绘本、上传页面（本地预识别 → 待校对 → 可用）、维护题库；题库题目同样过自检 |
| 没有家长侧、没有授权与删除 | 一次性家长 token、只读已发布周报、可撤回授权并删周报；管理员可"删除全部记录"（一次性连带会话/问答/建议/周报） |

## 6. 隐私与数据生命周期（规范 §5.7 / §6）

- 原图默认**不落盘**（`KEEP_PAGE_IMAGE=0`），只在内存里生成一张小缩略图给教师端看；
  绘本库页面图是老师主动上传的教学资源，另存于 `data/library/`。
- 音频不存：ASR 音频处理完即丢。TTS 播报缓存按文本哈希复用，因此：会话结束时删掉**本场产生的**文件
  （其他并行会话还在用的保留），启动时再扫一遍、清掉超过 `speech.KEEP_DAYS`（7 天）的残留。
  回复句里会复述孩子原话（如“你说「风筝」了”），这类缓存不能永久留在磁盘上。
- 会话结束后工作内存清空（`current / last_turn / history`），只保留数据库里的短文本记录。
- 家长撤回授权 → 该孩子的周报与快照一并删除。
- 教师端所有敏感操作写 `audit_log`。

```bash
python -m pytest tests -q                 # 100 条：内容闸门 / 画面接地 / 接口全链路 / 网络摄像头代理（含 MJPEG、Basic/Digest 登录、IP 钉死）/ WebSocket / 离线守卫 / 播放缓存清理 / 语音回答

python _tools\recheck.py                  # 九步复核：测试/导入/前端/服务/冒烟/浏览器/防护/离线/仓库，换个通道再证一遍

```

`live_smoke.py` 会打印摘要/提问的自检结论、建议条数、周报分数、运行自检每一项状态，
以及真实的 OCR/VLM 模式（`rapidocr` / `vlm:qwen2.5vl:3b` 这类），可以直接当作部署后的冒烟验收。

## 9. 机器人端可用性（网差了也还能用）

大部分时间这套东西跑在教室里的机器人/平板上，所以机器人端不能假设"网络总是好的"。
下面每一行都是 `robot.js` 里实际存在的分支，不是设计意图：

| 现场情况 | 机器人的反应 | 参数 |
| --- | --- | --- |
| 网络半死（连着但收不到包） | WebSocket 心跳，超时就主动断开重连 | 每 15s 发 ping，25s 无 pong 判死 |
| 连续 3 次连不上 | 自动切「兼容模式」：HTTP 轮询 + 表单上传，拍照/回答照常 | 轮询 2s |
| 识别迟迟没结果 | 看门狗恢复按钮，提示重拍，不会永远转圈 | 25s |
| 会话已被老师结束 / 设备不匹配 | 停在一个明确提示上，不再无意义重连 | 关闭码 4401 / 4404 |
| 平板息屏、切后台、断网 | 回到前台或网络恢复时立即重连/继续轮询 | `visibilitychange` / `online` |
| 服务端正在识别上一张 | 心跳照常回，不被长任务堵住 | 识别任务在后台跑 |
| 单条消息出错（图坏了、字段缺了） | 回一句人话让孩子重来，连接不断 | — |
| 重连时上一张还在识别 | 结果不丢：进事件总线，重连后由 snapshot 补上 | — |

每一种降级都会在机器人顶部状态条写明（`实时` / `重连中` / `兼容模式` / `已结束`），
不会静默失败。部署、开机自启、https 与局域网限制、故障排查见
[docs/ROBOT_OPS.md](docs/ROBOT_OPS.md)。

### 屏幕与输入方式也不是一种

教室里的设备很杂：7 寸小屏、10 寸平板、横屏一体机，有键盘的没键盘的。
`device.js` 启动时探测屏幕宽度/方向/内存/浏览器能力，写到 `<html data-screen>`，CSS 据此分三档
（compact / regular / wide）调字号、按钮尺寸和留白；全面屏的圆角用 `env(safe-area-inset-*)` 避开。

机器人上通常没有键盘，所以回答默认可以「**按住说话**」：录音在本地转成 16k 单声道 WAV 再上传，
和文字回答走同一条理解链路；不支持录音的设备会自动收起语音按钮，不会出现按了没反应的按钮。
同时支持 Pointer 事件与空格键（接键盘的机器人也能用），按住超过 10 秒自动停。

**翻页不用按快门**：摄像头/屏幕预览时会做极轻的帧差检测（40×40 采样、400ms 一次），
画面从「在翻」回到「稳住」且确实换了页，就自动拍下，1.5 秒后自动用这张（不对点【重来】）。
误拍有质量闸门兜底，漏拍就手动按一下；开关在面板里，默认开启。

**换设备先自检**：浏览器打开 [`/device-check`](http://127.0.0.1:8000/device-check)，
一页看完能力清单、摄像头预览（多摄像头可切换）、网络摄像头试连（ESP32/手机/USB 桥接）、
麦克风电平、喇叭提示音、网络往返，并可一键复制设备信息发给技术老师。
不读孩子数据，不需要登录；试连成功的地址会写进取图面板的记忆列表。

## 10. 性能实测

数字来自 `python _tools\bench.py 20`：进程内直接跑 A0→A11，**不含**网络、浏览器、
以及产品刻意安排的"停 8 秒看图"。机器是普通 Windows 开发机，模型全部 `stub`，
所以这里的耗时是**除模型推理外**的固定开销——真实链路里模型占大头，但这一段是你能控的。

| 阶段 | p50 | p95 | 说明 |
| --- | --- | --- | --- |
| A0 拍摄质检 | 13ms | 14ms | PIL 解码 + 糊/暗/反光判断，在线程里跑 |
| A1 文字识别 ‖ A2 画面理解 | 0ms | 0ms | stub 不发请求；真实模式取两者较慢的那个 |
| A3 三层摘要 | 0ms | 0ms | stub 走规则 |
| A11 摘要自检 | 13ms | 16ms | 纯规则，内容闸门 |
| A4 提问 | 3ms | 4ms | 题库命中，不调模型 |
| A11 提问自检 | 12ms | 14ms | 纯规则 |
| **单页合计（page_total）** | **52ms** | **54ms** | 含落库 |
| **端到端（机器人按下到出结果）** | **61ms** | **64ms** | 含上报与返回 |
| 回答链路 | 13ms | 16ms | stub TTS/ASR 立即返回 |

做了哪些事（按收益排序）：

1. **埋点批写**：原来每记一条 metrics 就新建一次 SQLite 连接（实测 10ms/条），一页 8 条
   白白花掉约 80ms。改成内存缓冲、出口一次 `executemany`，把单页从 124ms 降到 52ms。
2. **模型与图片处理不占事件循环**：质检、缩略图、OCR、VLM、ASR、TTS 全部 `asyncio.to_thread`；
   后台识别期间 WebSocket 心跳照常回。
3. **TTS 与"停 8 秒"并行**：原来先等完 8 秒再合成语音，现在合成在等待期间就做完，
   真实 TTS 模式下少等 0.2~0.8s。
4. **缩略图与识别并行**：教师端看到的缩略图不再让提问等它。

并发：4 台机器人同时拍页，整体 142ms 完成（串行预期 244ms，约 1.7 倍吞吐，28 页/秒）。
上不去更高是因为 stub 阶段本就是 CPU 密集 + SQLite 串行写；真实模式下大部分时间在等模型，
并发收益会更接近线性。

对事件循环的连续占用：单页最长约 25ms（两段规则自检），远低于 25s 的心跳超时，
所以"一个孩子在识别"不会让另一个孩子的心跳掉线。

真实链路怎么看：教师端运维面板的"最慢页面"直接读 `metrics` 表；`page_total` 与新加的
`A3_summary / A4_ask / A11_summary / A11_question` 都能单独看到。接上园内 GPU 后用同一条
命令复跑，就是这套硬件的真实预算。

## 11. 已知边界

- **演示模式只在降级时出现**：某个引擎连不上或没装（OCR 取库内缓存或空、VLM 无语义、ASR 脚本化转写、
  TTS 提示音）时，界面与 `/healthz` 会明确标 `demo_mode`，不会假装能用。真实部署的自检会指出是哪一项。
- 单进程内存态（事件总线、会话运行时）适合一个园区单机部署；要多实例需把 `EventBus` 与
  `RUNTIMES` 换成 Redis 之类的共享层。
- 拍照质量阈值按 720p 教室实拍设定（`app/services/vision.py` 顶部），换设备需重标。
- 屏幕截图/剪贴板来源的图常见“屏幕摩尔纹”与缩放模糊，质检会比实拍更容易判“糊”；
  这是有意的保守设定，宁可请老师重拍一张，也不让模型去猜。
- 家长周报只做"参与与阅读线索"，不做能力评价——这是产品红线，不是技术限制。
